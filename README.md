# KennysVideo

**简体中文** | [English](README.en.md)

面向 Windows 的开源视频客户端，集影视发现、资源搜索、在线播放、剧集管理和观看历史于一体。下载后即可安装使用，无需自行部署本地服务。

KennysVideo 基于 [KeyRotate/LibreTV-App](https://github.com/KeyRotate/LibreTV-App) 二次开发，其上游为 [LibreSpark/LibreTV](https://github.com/LibreSpark/LibreTV)。修改版由 KennysPan 维护，重点优化 Windows 桌面交互、播放器全屏、海报加载、品牌界面和双源版本更新体验。

[国内下载（Gitee）](https://gitee.com/kennysPan/kennys-video/releases/latest) · [GitHub 下载](https://github.com/KennysPan/KennysVideo/releases/latest) · [开源来源与许可](#开源来源与许可)

## 功能详解

### 1. 首页推荐与影视发现

- 展示豆瓣相关影视推荐、分类标签、影片名称、评分和海报，便于浏览不同类型的内容。
- 支持电影、电视剧、综艺、动画、纪录片和短片等分类入口。
- 影片推荐行支持横向滚动、可见滚动条及左右翻页按钮，便于在普通窗口内浏览更多条目。
- 页面下滑到一定距离后显示右下角“返回顶部”悬浮按钮。
- 推荐内容取决于第三方接口返回的数据；可在设置中调整推荐开关及豆瓣接口模式。

### 2. 多数据源搜索与详情

- 按影片名称或关键词搜索已选数据源，查看搜索结果并进入详情与剧集列表。
- 支持管理内置数据源、全选、全不选和选择普通资源，搜索时沿用用户的来源选择。
- 支持添加、编辑、启用和删除自定义 API，配置名称、接口地址及可选详情地址。
- 详情区域展示可用剧集并提供排序操作，方便定位要播放的集数。
- 保留搜索历史，减少重复输入。

自定义 API 需要符合应用当前支持的采集接口结构；填写任意网页地址并不意味着能够作为视频源使用。资源是否可搜索或播放，取决于来源接口及实际播放地址的可用性。

### 3. 分类筛选

- 按内容类型、题材、地区等条件筛选影视条目。
- 支持热度、时间、评分等排序选项；具体筛选维度随豆瓣接口模式变化。
- 通过影片卡片衔接搜索、详情与播放流程，保持首页和筛选页的一致操作方式。

### 4. 在线播放与剧集控制

- 基于 DPlayer 提供播放、暂停、音量、静音、时间显示、进度拖动、倍速、截图等播放器操作。
- 通过 hls.js 解析与播放 HLS／M3U8 流，配置缓冲、分片重试和部分媒体错误恢复逻辑。
- 提供上一集、下一集、剧集选择、顺序切换与自动连播开关。
- 支持播放进度保存，在符合恢复条件时继续上次播放位置；观看历史记录当前影片、来源和集数。
- 提供画面适配模式及垂直位置调整，适应不同比例的视频内容。
- 支持播放器快捷键，并提供 Alt + 左方向键切换上一集、Alt + 右方向键切换下一集。
- 普通窗口采用较紧凑的播放器高度；桌面全屏通过原生窗口接口覆盖整个屏幕，并同步调整播放区域与控制栏布局。

截图、倍速及媒体恢复等操作受视频格式、来源响应和运行环境影响；程序中的恢复与过滤逻辑不保证所有第三方视频均可正常播放。

### 5. 海报与默认封面

- 首先显示本地 KennysVideo 默认封面，避免海报尚未加载时出现空白区域。
- 真实海报加载成功后自动替换默认封面；缺失或加载失败时保留默认图。
- 首页、搜索和筛选条目使用统一封面逻辑，默认封面采用“左侧小头像、右侧名称与说明”的品牌布局。
- 针对豆瓣图片，通过 Rust 原生请求处理请求头与图片响应，再交给前端显示。
- 前端采用请求队列、最多 4 个并发下载及有界缓存，减少重复请求与集中加载压力。
- 原生图片通道仅接受指定豆瓣 HTTPS 图片路径，校验响应类型、文件头和大小，单张图片限制为 5 MiB。

### 6. 观看历史与本地配置

- 在本地保存观看记录、来源、集数、播放位置和搜索历史；当前观看历史最多保留 50 条。
- 播放过程中定期保存进度，支持从历史入口继续观看及清空历史记录。
- 支持将应用设置、所选来源、自定义来源以及相关历史导出为 JSON，再通过导入功能恢复。
- 配置导入会检查文件格式、大小与数据摘要，以识别不匹配或损坏的配置文件。
- 设置页保留本地数据清理入口；界面中的“清除 Cookie”用于清理应用相关本地存储。

以上记录主要保存在本机 WebView 的 localStorage 中，不提供账号云同步。关闭窗口偏好另由原生端保存至应用配置文件。

### 7. 设置与界面交互

- 支持内容过滤、分片广告过滤、豆瓣热门推荐和豆瓣接口模式等开关。
- 分片广告过滤通过 HLS 加载逻辑处理可识别的片段，不保证移除全部来源广告；关闭该功能可用于排查播放兼容性问题。
- 设置页统一卡片宽度、间距、文字层级与控件尺寸，并适配较窄窗口。
- 使用深色背景、青色主题和统一头像，覆盖页面标识、默认图片、窗口、托盘及安装相关图标。
- 常规界面文字禁用选中，减少误拖选；搜索框等输入区域仍支持正常编辑与选择。

### 8. Windows 窗口与系统托盘

- 启动时显示居中的普通窗口，初始尺寸为 1000 × 680，可拖动边框调整大小。
- 使用 Windows 原生标题栏，提供最小化、最大化／还原与关闭按钮。
- 启用单实例：软件运行时再次点击图标，会唤起并聚焦现有窗口。
- 点击关闭按钮时，可选择“退出程序”或“最小化到系统托盘”，提供确定、取消及“不再提示”选项。
- 每次重新弹出关闭确认框时，默认选中最小化；设置页可随时修改已经记住的关闭偏好。
- 系统托盘提供恢复窗口和退出入口；标题栏最小化按钮仍使用常规任务栏最小化行为。
- 安装程序维护桌面及开始菜单快捷方式，并刷新对应应用图标。

### 观看提示与自定义数据源

- 自定义 API 可加入聚合搜索，并继续支持影片详情、剧集及播放流程。
- 当前版本已移除底部“片库”和单来源浏览页面，保持主导航简洁。
- 进入播放页面时弹窗提示“切勿相信视频中的广告”；确认后不常驻遮挡，同页切集不重复提醒。

### 应用内 BUG 反馈

- 设置页与播放页提供反馈表单，提交问题、复现步骤和可选回复邮箱，失败保留输入，重试使用相同编号避免重复入队。
- 客户端通过维护者的 HTTPS 接口提交报告，不包含 SMTP 授权码；普通用户无需自行部署服务。
- 服务端使用 Python、Gunicorn、SQLite、Nginx 与 QQ SMTP，先持久保存再发送 HTML/纯文本邮件，带现有头像、品牌配色和问题分区。
- 报告在反馈服务器最多保存 30 天，不自动附带观看记录、视频地址、自定义 API、日志或截图。
- 自建服务的部署说明和接口契约见 [server/feedback](server/feedback/)。真实提交、实际收件及 HTML 排版已验证；原生 WebView2 自动化桌面验收仍未完成，详见 [验证记录](docs/bug-feedback.md)。

## 运行流程

| 场景 | 处理过程 |
| --- | --- |
| 启动 | 检查单实例 → 创建或恢复窗口与托盘 → 加载前端资源和本地偏好 → 检查新版本。 |
| 搜索与播放 | 用户输入关键词 → 查询所选来源 → 展示详情与剧集 → 将播放地址交给播放器。 |
| 海报显示 | 本地默认图 → 异步请求真实海报 → 成功后替换，失败则保留默认图。 |
| 进度记录 | 播放器获取当前时间与集数 → 写入本地记录 → 后续打开时尝试恢复。 |
| 版本更新 | 查询发布源 → 比较版本 → 用户下载 → 分块上报进度 → SHA256 校验 → 用户确认安装。 |

应用使用第三方接口获取影视信息及播放地址，客户端负责搜索、展示和播放。本仓库不存储或分发影视视频内容；推荐与在线播放需要相应网络服务可用。

## 双源更新与安装机制

### 版本检测与自动换源

1. 启动时检查版本，设置页也提供“检查更新”按钮。
2. 优先获取 GitHub 的版本信息，等待预算为 3 秒；超时、请求失败或返回的发布信息不可用时，转向 Gitee。
3. 下载优先尝试 GitHub。出现连接超时、下载停滞，或下载至少 5 秒后的平均速度低于 64 KiB/s 时，尝试 Gitee 的同版本安装包。
4. 换源会重新开始下载，不是断点续传；进度随当前来源重新计算。

### 下载进度与校验

- 更新窗口展示当前版本、目标版本、下载进度及相关状态。
- 已知文件大小时，按实际收到的字节计算百分比；响应未提供大小时，显示不确定进度状态。
- 下载完成后进入校验，只有校验并保存成功才显示完成状态。
- 通过 SHA256 检查下载文件与发布摘要的一致性，在启动安装前再次校验。
- 校验失败、下载失败时显示错误并提供重试；由用户点击确认后退出应用并启动安装程序。
- 校验用于检查文件是否与发布摘要一致，不等同于 Windows Authenticode 发行者签名。

### 覆盖升级

- 安装器检测已安装版本：未安装时执行首次安装，检测到旧版时在原目录覆盖升级，并阻止降级安装。
- 延用原有应用安装标识，支持从旧版 LibreTV 安装升级至 KennysVideo，保留本地设置和观看历史。
- 该检测针对通过安装程序安装的版本，不会扫描并识别任意文件夹中的便携程序。
- 旧版若无法在线更新，可手动下载最新安装包并覆盖安装。

### Windows 构建步骤

开发者需要 Node.js／npm、Rust 工具链、MSVC C++ 构建工具、Windows SDK 与 WebView2。克隆本仓库或解压对应版本源码后，在项目根目录执行：

```powershell
npm ci
npm run dev
```

构建 Windows x64 NSIS 安装包：

```powershell
rustup target add x86_64-pc-windows-msvc
npm run tauri -- build --bundles nsis --target x86_64-pc-windows-msvc -- --locked
```

修改基础样式后可执行 npm run build:css 重新生成样式文件。安装包通常输出至 src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/。发布辅助脚本 tests/prepareRelease.py 和 tests/packageSource.py 用于生成版本文件、校验信息与源码包，具体流程见 BUILDING.md 和 docs/updates.md。

## 回归验证

源码包中的验证脚本覆盖主题与默认图片、影片点击与缓存、横向浏览、播放器全屏、返回顶部、关闭确认、更新进度、单实例和快捷方式图标等场景；Rust 测试包含版本处理、下载换源、进度与校验逻辑。

其中，浏览器验证使用 Playwright 与本机 Edge；Windows 单实例和快捷方式验证使用 PowerShell；更新核心包含本地 HTTP 测试。需要真实网络的检查与常规本地检查分开执行，具体依赖与命令以源码内说明为准。
