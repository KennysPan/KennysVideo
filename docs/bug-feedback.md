设置页与播放页共用反馈弹窗，提交问题标题、描述、复现步骤、可选回复邮箱，以及界面展示的软件版本和平台。不自动读取截图、日志、观看记录、视频地址或自定义 API 配置。隐私说明披露服务器保留报告最多 30 天，并使用带密钥的 IP 哈希限制滥用；邮件副本按问题处理需要保留。

服务器先将报告写入 SQLite，返回 202 / success:true / status:queued。界面明确提示已保存并加入发送队列，不将该状态称为实际收件。独立 worker 使用验证证书的 QQ SMTP SSL 465 发送，失败最多重试 5 次。HTTP 超时后重试复用相同 request_id，修改报告内容后使用新编号，避免请求响应丢失造成重复入队。完整契约及部署说明位于 `server/feedback`。

反馈邮件提供 HTML 和纯文本两种内容：使用现有头像、深色品牌页头、青蓝色点缀，分区展示问题与复现步骤，附版本、平台、提交时间及报告编号；提供回复邮箱时可点击回复。头像作为 CID 资源随邮件嵌入，不依赖外部图片网址。所有用户输入均作 HTML 转义。

## 请求约定

- POST https://api.web3forms.com/submit，Content-Type 与 Accept 均为 application/json。
- 必填：access_key、subject、from_name、message、botcheck:false。
- 可选：email，作为反馈者填写的回复邮箱。
- message 仅包含填写的问题标题、问题描述、复现步骤、软件版本和运行平台。
- 不自动读取截图、日志、观看记录、影片地址或自定义 API 配置。
- 发送前界面明确说明数据将通过 Web3Forms 转交给开发者。
- 使用 strict-origin 引用来源策略，仅允许浏览器发送来源地址，不包含页面路径、搜索参数或影片地址；不伪造来源或代理请求。

## 结果处理

15 秒等待超时；同一时刻只允许一个请求，不自动重试。只有 HTTP 成功且 JSON success 严格为 true 才显示“服务已接收”。此状态不代表邮箱实际投递已验证。

失败保留输入，提供手动重试；HTTP 429 提示频率或额度问题；超时明确无法确认是否送达。发送中锁定关闭操作和字段，成功后阻止重复点击，关闭成功窗口后重置表单。未配置通道不发送请求。
